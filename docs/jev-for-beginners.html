検証ノート ・ 2026年9月

Jevって結局なに?
ツールを1本作って確かめてみた

2026年9月に登場した新しいAIモデル「Jev(ジェブ)」。今までのAIと何が違うのかを、実際にツールに組み込んで試しました。AI駆動開発をしている人なら分かる言葉でまとめます。

  • Jevは文章を書かないAI。こちらが用意した選択肢から答えを選んで、その確率を返すだけ。
  • そのかわり、とても速くて(約0.5秒)、とても安い。ChatGPTやClaudeの数十〜数百分の1。
  • プログラムの中に置く「かしこいif文」だと思うと、しっくりくる。

今までのAI(LLM)と何が違うの?

ChatGPTやClaudeのようなAI(LLM)は、文章で考えて、文章で答えます。Jevは、選択肢から選んで、確率を返します。作りがまったく違います。

開発元のTypeSafe AIは、心理学の言葉を借りて説明しています。人間の頭には、パッと直感で判断する「システム1」と、じっくり考える「システム2」がある。今までのAIはシステム2、Jevはシステム1だ、と。

熱いやかんに触って手を引っ込めるのに、じっくり考える人はいません。プログラムの中にも「考えなくていいから、速く・安く・確実に判定してほしい」場面がたくさんあります。Jevは、そこを担当するAIです。

Jevには何を渡して、何が返ってくるの?

渡すものは、状況と、質問と答えの選択肢の2つだけです。実際に試した例です。

渡すもの

「それでは次のセッションに移りたいと思います。スポンサーのご紹介です」

この「セッション」は、どちらの意味?

AAIツールとのひと続きの会話
Bイベントや勉強会の発表枠

返ってくるもの

A
2%
B
98%

文章ではなく数字で返ってくるので、プログラムでそのまま if (B > 0.5) のように使えます。「JSONで返してと頼んだのに、余計な前置きがついてきた」が、仕組み上起きません。

作ってみたツール: リアルタイム技術用語ガイド

勉強会や学習動画を聞いていて、知らない用語が出てきて、そこから先の話に置いていかれた経験はありませんか。それを助けるツールを作りました。聞きながら開いておくと、出てきた技術用語のひとこと解説が流れてきます。

  1. Chromeの機能勉強会(Zoomのブラウザ版)や動画(YouTube)を再生しているタブの音声を、文字起こしする
  2. ふつうのプログラム(Python)出てきた言葉を、用語集(約1,370語)から探す
  3. ここだけJev紛らわしい言葉だけ、「技術用語として使われた? それとも日常語?」と聞く
  4. ふつうのプログラム技術用語だったら、ひとこと解説のカードを画面に出す。「もう知ってる」を押した用語は、もう出さない
聞こえてきた言葉

「このスキルはプラグインとして配布していて、サブエージェントから呼び出せます」

Jevの判定: 技術用語 100% → 解説を出す

スキル (Agent Skills)中級

AIに「この作業はこの手順で」と教えておく指示書のパッケージ。人間の能力の意味のスキルとは別物。

聞こえてきた言葉

「彼はプレゼンのスキルが高いので、転職エージェントにも評価されてました」

Jevの判定: 日常語 100% → 何も出さない

「スキル」も「エージェント」も用語集にある言葉ですが、ここでは人の能力と転職サービスの話。文字の一致だけでは見分けられず、かといってLLMに毎回聞くほどでもない。Jevにちょうどいい仕事でした。

実験して分かった4つのこと

分かったこと(1) 聞き方で、答えのキレが変わる

同じ内容でも、「はい/いいえ」で聞くより、「AとBのどっち?」で聞くほうが、はっきり答えてくれます。

Jevは、質問を字面どおりに読みます。空気を読んで察することはしません。だから、比べる相手をこちらが言葉にして渡すのがコツです。

分かったこと(2) とにかく量をさばける

ためしに、用語集の全部(1,374語)について、2時間の勉強会の全発言に「この用語、出てきた?」と総当たりで聞いてみました。

LLMで同じことをやったら、時間もお金も現実的ではありません。これがJevの一番の強みです。

分かったこと(3) 聞き間違いに強い。でも万能ではない

総当たりで聞くと、音声認識の聞き間違いまで拾ってくれました。

  • フラバナ→Grafana
  • Gitッハブコパルト→GitHub Copilot
  • PYON→Python

一方で、「はい/いいえ」の総当たりだと、答えの確率が50〜90%あたりに固まってしまいました。

結局、「プログラムで探せるものはプログラムで探して、迷うところだけJevに聞く」のがいちばん良かった、というのが今回の結論です。総当たりは、録画を1本流して聞き間違いのパターンを集める、といった「たまにやる調査」に向いています。

分かったこと(4) 正直なところ、Jevじゃなくてもできた

同じ判定をClaudeのHaiku(小さくて速いモデル)にやらせてみたら、同じようにできました。しかもHaikuなら、解説文まで一緒に書いてくれます。Jevは文章を書けないので、解説は用語集として先に用意しておく必要があります。

今回のツールは「1人が、数秒遅れても困らない頻度で使う」ものなので、Jevの速さと安さは、実は決め手になりませんでした。

じゃあ、Jevはどんなときに使うといいの?

  • 一瞬の判断がほしい入力中のフォーム、ゲーム、音声のやり取りなど、0.1〜0.5秒で答えがほしい場面
  • ものすごい回数を判定したい何十万件のデータの分類、全ログのチェックなど
  • 答えの形が壊れると困るプログラムがそのまま使うので、決まった選択肢以外が返ってきては困る場面

逆に、説明してほしい・考えてほしい・作ってほしいなら、今までどおりLLMの出番です。どちらかを選ぶものではなく、組み合わせて使うものだと思うのがよさそうです。

LLMに考えさせて
設計する、説明する、コードを書く、用語集の解説を書く
+
Jevに仕分けさせる
分類する、振り分ける、チェックする、どっちの意味か決める

使うときのコツ

  1. 「はい/いいえ」より「AとBのどっち?」で聞く
  2. 1つの質問では、1つのことだけ聞く
  3. 「文章の中から用語を抜き出して」はできない。候補はプログラムで作って、Jevには選ばせる
  4. プログラムで決められることは、先にプログラムで決める
  5. 質問はたくさん並べても遅くならない。まとめて聞く
