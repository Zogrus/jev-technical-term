# Jevって結局なに? ― ツールを1本作って確かめてみた

2026年9月に登場した新しいAIモデル「Jev(ジェブ)」。
「今までのAIと何が違うの?」を確かめるために、Jevを使ったツールを実際に1本作って、いろいろ試しました。
AI駆動開発をしている人なら分かる言葉で、分かったことをまとめます。

> 図つきで読みたい人は、同じ内容のHTML版(`jev-for-beginners.html`)をどうぞ。

## 30秒でまとめると

- **Jevは文章を書かないAI**です。こちらが用意した選択肢の中から**答えを選んで、その確率を返すだけ**。
- そのかわり、**とても速くて(約0.5秒)、とても安い**(ChatGPTやClaudeの数十〜数百分の1)。
- プログラムの中に置く「**かしこいif文**」だと思うと、しっくりきます。

## 1. 今までのAI(LLM)と何が違うの?

ChatGPTやClaudeのようなAI(LLM)は、**文章で考えて、文章で答えます**。
相談にも乗ってくれるし、コードも書いてくれる。そのかわり、答えが出るまで数秒〜数分かかり、料金もそれなりにかかります。

Jevは、まったく違う作りです。

| | 今までのAI(LLM) | Jev |
|---|---|---|
| 答え方 | 文章を書く | 選択肢から選ぶ(+確率) |
| たとえるなら | じっくり相談に乗ってくれる先輩 | 一瞬で仕分ける、改札機や仕分け係 |
| 速さ | 数秒〜数分 | 約0.5秒 |
| 料金 | それなり | けた違いに安い |
| 得意 | 考える・説明する・作る | 分類する・判定する・選ぶ |
| できないこと | ― | 文章を書く、説明する、コードを書く |

開発元のTypeSafe AIは、これを心理学の言葉を借りて説明しています。
人間の頭には、**パッと直感で判断する「システム1」**と、**じっくり考える「システム2」**がある。今までのAIはシステム2、Jevはシステム1だ、と。

熱いやかんに触って手を引っ込めるのに、じっくり考える人はいません。
プログラムの中にも、「じっくり考えなくていいから、速く・安く・確実に判定してほしい」場面がたくさんあります。Jevは、そこを担当するAIです。

## 2. Jevには何を渡して、何が返ってくるの?

渡すものは2つだけです。

1. **状況**(文章やデータ)
2. **質問と、答えの選択肢**

たとえば、こう聞きます。

> **状況:** 「それでは次のセッションに移りたいと思います。スポンサーのご紹介です」
> **質問:** この「セッション」は、どちらの意味?
> **A:** AIツールとのひと続きの会話
> **B:** イベントや勉強会の発表枠

返ってくるのは、これだけです。

> **A: 2% / B: 98%**

文章は1文字も返ってきません。だから、プログラムでそのまま `if (Bの確率 > 0.5)` のように使えます。
LLMでよくある「JSONで返してと頼んだのに、余計な前置きがついてきた」が、仕組み上起きません。

## 3. 作ってみたツール: リアルタイム技術用語ガイド

勉強会や学習動画を聞いていて、**知らない用語が出てきて、そこから先の話に置いていかれた**経験はありませんか。
それを助けるツールを作りました。

- 勉強会(Zoomのブラウザ版)や動画(YouTube)を再生しているタブの音声を、Chromeの機能で文字起こしする
- 出てきた技術用語を、用語集(約1,370語)から探す
- **紛らわしい言葉だけ、Jevに「どっちの意味?」と聞く**
- 技術用語だったら、ひとこと解説のカードを画面に出す

Jevの出番は、3つ目です。たとえば「スキル」という言葉。

- 「このスキルはプラグインとして配布していて…」→ Claude Codeの機能の話 → **解説を出す**
- 「彼はプレゼンのスキルが高いので…」→ 人の能力の話 → **出さない**

これを、文字の一致だけで見分けるのは無理です。でもLLMに毎回聞くほどのことでもない。Jevにちょうどいい仕事でした。

**かかったお金:** 2時間の勉強会を聞いて、**約3円**(約$0.02)。

## 4. 実験して分かった4つのこと

### 分かったこと(1) 聞き方で、答えのキレが変わる

同じ内容でも、「はい/いいえ」で聞くより、「AとBのどっち?」で聞くほうが、はっきり答えてくれます。

| 発話 | 「はい/いいえ」で聞いた | 「どっち?」で聞いた |
|---|---|---|
| このスキルはプラグインとして配布していて… | はい 69% | **技術用語 100%** |
| 彼はプレゼンのスキルが高いので… | はい 2% | **日常語 100%** |
| 次のセッションに移ります。スポンサーの… | はい 36% | **日常語 98%** |

Jevは、質問を**字面どおりに**読みます。「空気を読んで察する」ことはしません。
だから、**比べる相手をこちらが言葉にして渡す**のがコツです。

### 分かったこと(2) とにかく量をさばける

ためしに、用語集の全部(1,374語)について、2時間の勉強会の全発言に対して「この用語、出てきた?」と総当たりで聞いてみました。

- 判定の数: **約50万回**
- かかった時間: **約4分**
- かかったお金: **約290円**($1.90)

LLMで同じことをやったら、時間もお金も現実的ではありません。これがJevの一番の強みです。

### 分かったこと(3) 聞き間違いに強い。でも万能ではない

総当たりで聞くと、音声認識の聞き間違いまで拾ってくれました。

- 「フラバナ」→ Grafana
- 「Gitッハブコパルト」→ GitHub Copilot
- 「PYON」→ Python

一方で、「はい/いいえ」の総当たりだと確率が50〜90%あたりに固まってしまい、「ここから上は正解」という線がきれいに引けませんでした。はっきり出てきている「スキル」を見逃したり、話に出ていない用語を拾ったりします。

結局、**「プログラムで探せるものはプログラムで探して、迷うところだけJevに聞く」のがいちばん良かった**、というのが今回の結論です。

### 分かったこと(4) 正直なところ、Jevじゃなくてもできた

同じ判定をClaudeのHaiku(小さくて速いモデル)にやらせてみたら、**同じようにできました**。しかもHaikuなら、解説文まで一緒に書いてくれます(Jevは文章を書けないので、解説は用語集を用意する必要があります)。

今回のツールは「1人が、数秒遅れても困らない頻度で使う」ものなので、Jevの速さと安さは、実は決め手になりませんでした。

## 5. じゃあ、Jevはどんなときに使うといいの?

次のどれかに当てはまるときです。

- **一瞬の判断がほしい** … 入力中のフォーム、ゲーム、音声のやり取りなど、0.1〜0.5秒で答えがほしい場面
- **ものすごい回数を判定したい** … 何十万件のデータの分類、全ログのチェックなど
- **答えの形が壊れると困る** … プログラムがそのまま使うので、決まった選択肢以外が返ってきては困る場面

逆に、説明してほしい・考えてほしい・作ってほしいなら、今までどおりLLMの出番です。
**LLMに考えさせて、Jevに仕分けさせる。** 組み合わせて使うものだと思うのがよさそうです。

## 6. 使うときのコツ(今回の学び)

1. 「はい/いいえ」より「AとBのどっち?」で聞く
2. 1つの質問では、1つのことだけ聞く
3. 「文章の中から用語を抜き出して」はできない。候補はプログラムで作って、Jevには選ばせる
4. プログラムで決められることは、先にプログラムで決める
5. 質問はたくさん並べても遅くならない。まとめて聞く
