# Jev 検証ノート(技術者向け)

TypeSafe AI の System One モデル「Jev」を、実際のツール(リアルタイム技術用語ガイド)に組み込んで検証した記録。
検証日: 2026-09-17〜18。モデル: `jev-1.13.0`(`jev-latest`)。

数値は、断りがない限り**このプロジェクトでの実測**。TypeSafe公称の値は「公称」と明記する。

## 1. Jevとは(前提の整理)

- 入力: `state`(テキストまたはJSON。画像・音声は不可)+ 型付きの質問(複数可)
- 出力: 質問ごとの答えと確率。文章は生成しない
- 質問の型は3つ

| 型 | 返すもの |
|---|---|
| Choice | 選択肢から1つ + 各選択肢の確率 + confidence(最大255択) |
| Score | 順序つきの段階評価 + 確率 |
| Noul | Yesである確率(0〜1) |

- 料金: 入力 $0.042 / 100万トークン、出力は無料(公称。実測の請求額とも一致)
- レート上限: 25万トークン/秒、1,200リクエスト/分(公称)
- レイテンシ: 公称70〜500ms(米国西海岸計測)。**日本からの実測は1コール約0.5秒**(中央値0.52秒、質問5〜10個)
- 公式が明記している弱点: 質問を字面どおりに読む / 数を数えられない・数値の近さが苦手 / 日付比較が苦手 / 多段推論・二重否定に弱い / 無関係な情報が多いstateで精度が落ちる / stateに紛れた指示文に誘導されうる

## 2. 作ったもの

勉強会や学習動画を聞く初心者向けに、会話に出た技術用語のひとこと解説をリアルタイムに出すローカルWebアプリ。

```
視聴中のタブ音声 ──(getDisplayMedia)──▶ Chrome内蔵の音声認識(Web Speech API)
   │ 発話が確定するたびにテキスト化
   ▼
ブラウザ(素のJS): クールダウン / 「もう知ってる」 / 表示レベル を管理(localStorage)
   │ POST /judge {発話, 直前の文脈, レベル}
   ▼
判定サーバー(Python標準ライブラリのみ・状態なし)
   ① 用語集(1,371語・別名 約2,960個)と文字列照合 … 1回0.03ms
   ② Jevに聞くか振り分け: 別の意味(other)を持つ語・短い別名だけ聞く。長い別名はそのまま採用
   ③ Jevを1回呼ぶ(質問を並列で載せる)
        ・用語集の候補 → Choice二択「技術的な意味 / 別の意味」
        ・用語集にないカタカナ語・英略語 → Choice4択「専門用語 / 日常語 / 固有名 / 認識誤り」
   ④ 確率0.5以上をカードとして返す
```

利用者が自分でキーを用意して呼び出すAIは**Jevだけ**(音声認識はChrome内蔵で無料・キー不要)。

## 3. 検証と結果

検証素材は、公開されている約2時間のLT会動画のYouTube自動字幕(=音声認識の生出力。「プラグイン→プラゲイン」のような崩れを含む)。20秒ごとに区切って362窓。

### 3.1 最初の構成(用語集35語、Noul + 必要度Score)

| 項目 | 実測 |
|---|---|
| 2時間分の処理 | 362コール / 32秒(6並列) |
| コスト | $0.016 |
| レイテンシ | 中央値0.52秒 / 90%点0.56秒 / 最大1.23秒 |
| 表示されたカード | 48件(目視で誤爆ゼロ) |

- 日常語の判別は効く: イベントの「セッション」は0.07〜0.14、AIとの会話の「セッション」は0.84。
- **「必要度」のScoreで足切りするのは有害だった。** MCPの初出が「MCPとかプラグインとか…」という列挙の中だったため「軽く触れただけ」と判定され、表示が32分遅れた。初出で出すのが正しく、必要度の判定は撤去した。
- **専門的な勉強会では、Jevのゲートの寄与は小さい。** Jevなし(辞書+クールダウンのみ)75件 vs Jevあり72件。差は主に「セッション」の誤爆防止分。曖昧語も、その場ではほぼ毎回技術的な意味で使われるため。

### 3.2 Noul(Yes/No)より、別の意味を明示したChoice(二択)

同じ発話・同じ用語を、2つの聞き方で同時に投げた結果。

| 発話 | 用語 | Noul: Yesの確率 | Choice: 技術的な意味 / 別の意味 |
|---|---|---|---|
| このスキルはプラグインとして配布していて… | スキル | 0.69 | **1.00** / 0.00 |
| 彼はプレゼンのスキルが高いので… | スキル | 0.02 | 0.00 / **1.00** |
| あのフックであの設定してるんですけど… | フック | 0.50 | **0.78** / 0.22 |
| クロードコードを効率的に使うために… | Claude Code | 0.82 | **0.99** / 0.01 |
| 次のセッションに移りたいと思います。スポンサーの… | セッション | 0.36 | 0.02 / **0.98** |

Noulの質問は「その語が出ているか」「技術的な意味か」「説明文と合致するか」を一度に判断させており、どれか一つでも自信がないと確率が割り引かれる。Choiceは、Pythonの照合で「語が出ている」ことを確定させたうえで「どちらの意味か」の一点だけを聞き、比べる相手(別の意味)も言葉で渡している。公式の言う「字面どおりに読む」「1つの質問に複数の判断を隠すな」がそのまま数字に出た。

**指針: Jevには「Aですか?」より「AとBのどちらですか?」で聞く。**

### 3.3 用語集にない語の検出

- 発話全体に「初心者が知らない専門用語が含まれるか」をNoulで聞く → 362窓中248窓(68%)で反応し、ゲートとして役に立たない。
- コードでカタカナ語(4文字以上)・英略語を拾い、**語ごとに**4択のChoiceで分類させる → 精度が高い。候補753件(ユニーク429語)を305コールで分類し、専門用語240 / 日常語118 / 固有名34 / 認識誤り37。グラファナ・サンドボックス・デプロイ等は専門用語、スポンサー・アジェンダ等は日常語、メルカリ・ズンダモン等は固有名、ブロードリス・ナレーチュ等は認識誤りに入った。

**指針: Jevは用語を「抜き出す」ことはできない。候補をコードで作り、1語ずつ選択肢つきで聞く。**

### 3.4 用語集を1,371語に拡充した後

| 設定 | 2時間で出るカード(クールダウン10分) |
|---|---|
| 初級から全部 | 226枚(約34秒に1枚) |
| 中級以上 | 89枚 |
| 上級のみ | 18枚 |

- Jevを呼んだのは362窓中217窓。別名 約2,940個のうちJevに聞く対象は1,156個(otherを持つ語 + 日本語5文字以下/英字3文字以下の別名)。
- **部分一致の事故は、Jevが安全網として弾く。** 「リストアップ」の中の「リストア」0.01、「カレンダー」の中の「レンダー」0.21、「リキュール」の中の「キュー」0.32、「メモリエンジニアリング」の中の「メモリ」0.05。
- **紛れようのない長い別名やスラングは、Jevに聞かないほうがよい。** 「トークンを溶かす」は二択にかけると落とされた(技術的な意味/日常語、という問いの立て方が合わない)。公式の「先に決定的な処理で絞ってからモデルに聞く」と同じ結論。
- 残る弱点: **短い発話は直前の文脈に引っ張られる。** AIの話の直後の「次のセッションで詳しく話します」が0.98で通る。誤爆のコストが低い(余計なカードが1枚出るだけ)ので許容している。

### 3.5 全量方式: 用語集の全語をJevに聞く

Pythonの照合をやめ、1,374語すべてについて「この発話で、この用語がその意味で使われているか」をNoulで聞く。

| 項目 | 実測 |
|---|---|
| 判定数 | 362窓 × 1,374語 ≒ 約50万判定 |
| 入力トークン | 45,236,260 |
| コスト | **$1.90**(1判定あたり約$0.000004、1窓あたり$0.0052) |
| 2時間分の処理時間 | 227秒(約2,200判定/秒) |
| 1発話あたりの待ち時間 | 中央値1.23秒 / 90%点1.43秒(250語ずつ6並列) |

- 1,374問(約12.4万トークン)を1コールに載せると `400 max_tokens_exceeded`。230〜250問(約2.1万トークン)なら通る。
- **強み(1): 別名の登録なしで、聞き間違いと言い換えを拾う。** フラバナ→Grafana 0.76、Gitッハブコパルト→GitHub Copilot 0.86、オープンテレメト→OpenTelemetry 0.89、PYON→Python、「プロンプトはガチャです」→AIガチャ、「人間による確認を行う」→ヒューマン・イン・ザ・ループ。
- **強み(2): 部分一致の事故がない。** 現行方式が6回誤爆した「M5スタック」の「スタック」(データ構造)は、6回とも0.00。
- **弱み: 確率が中間に寄り、きれいなしきい値が引けない。**

| 確率帯 | 0.9以上 | 0.8〜0.9 | 0.7〜0.8 | 0.6〜0.7 | 0.5〜0.6 |
|---|---|---|---|---|---|
| 件数 | 26 | 233 | 223 | 174 | 226 |

  - しきい値0.7: 文字どおり出ている語を落とす(クロードコード0.65で23回、スキル0.37で30回、フック0.40、「サブエージェントを見える化して」でサブエージェント0.00)。
  - しきい値0.5: 0.5〜0.7の帯で現行方式が拾っていない280件から35件を無作為に目視 → 約4割が正しい、約2割が微妙、約4割が誤り(話に出ていないPrettier・Hugging Face・Replit、「サブは捨てる」→サブエージェント等)。

| 方式 | 2時間のカード | 用語の種類 |
|---|---|---|
| 全量 しきい値0.5 | 415枚 | 250 |
| 全量 しきい値0.7 | 224枚 | 139 |
| 全量 しきい値0.9 | 21枚 | 14 |
| 現行(照合+二択) | 235枚 | 134 |

**結論: 常時処理は「コードで照合 → 紛らわしい語だけ二択」。全量方式は、録画を1本流して音声認識の聞き間違い表記を収穫するオフライン用途に向く。** 実際に、この1回($1.90)で見つけた19個の表記(フラバナ、Gitッハブ、コパルト、リポジト館、プロスタイプ、PYON 等)を別名に追加し、以後は安い現行方式のままで拾えるようにした。

### 3.6 「これ、Jevでないとできないのか?」

**できる。Jevは必須ではない。** 同じ紛らわしい発話10件をClaude Haiku 4.5に1回で判定させたところ、10件とも正解し、しかも用語の抜き出しと解説文の生成まで同時にこなした(Jevにはできない)。

| 観点 | Jev | Haiku 4.5(API利用時) | この用途での重み |
|---|---|---|---|
| 速度 | 実測 約0.5秒 | 1〜2秒の見込み(未計測) | 小。音声認識の確定に1〜3秒かかる |
| 2時間あたりのコスト | 約$0.02 | 約$0.6(入力$1・出力$5/100万トークンでの試算) | 小。個人利用では誤差 |
| 出力の型の保証 | あり | 構造化出力でほぼ同等 | 小 |
| キーの入手 | 早期アクセス。各自が申請 | 容易(ただしサブスクとは別契約) | 大。配布のハードルに直結 |

Jevの強みが効くのは、(a) 1回の判断が100ms単位で効く、(b) 1日に数百万回呼ぶ、(c) 出力の型が壊れると困る、のいずれかに当てはまるとき。今回の用途(個人が、数秒遅れても困らない頻度で使う)はどれにも当てはまらなかった。逆に、同じ仕組みを数千人が同時に使うホスティング型にするなら、約30倍のコスト差が効いてくる。

なお `claude -p`(Claude CodeのCLI)を毎回起動する方式は、起動だけで約14秒かかるためリアルタイム判定には使えない。

## 4. Jevを使うときの設計指針(今回の学び)

1. **「AとBのどちらか」で聞く。** Yes/Noは控えめな確率になりやすい。比べる相手を言葉で渡す。
2. **1つの質問に1つの判断。** 「出ているか」と「どの意味か」を分ける。前者はコードで確定させる。
3. **抜き出し・生成はさせない。** 候補はコードで作り、Jevには選ばせる。
4. **先にコードで絞る。** 紛れようのないものまで聞かない。聞くと、問いの立て方が合わずに落とされることがある。
5. **質問はいくら並べても安い。** 1コールに数十〜200問載せても待ち時間はほぼ変わらない(上限は入力トークン量。約2万トークン/コールは通り、約12万は通らない)。
6. **確率は、しきい値を実データで決める。** 公称は「校正済み」だが、聞き方しだいで分布は大きく変わる。
7. **stateは小さく。** 直前の文脈を渡すと判別の手がかりになる一方、短い発話では文脈に引っ張られる。
8. **全量の総当たりは、オフラインの知見収穫に使う。** 50万判定が$2・4分なので、「一度流して辞書を育てる」用途なら十分に安い。

## 5. 再現方法

```
python3 scripts/parse_subs.py <字幕.json3> data/raw/transcript.jsonl   # 字幕を時刻つきテキストに
python3 scripts/replay.py data/raw/transcript.jsonl --jev               # 現行方式で別名の当たり方を点検
python3 scripts/alljev_replay.py data/raw/transcript.jsonl              # 全量方式(約$2)
python3 scripts/alljev_report.py                                        # 全量方式と現行方式の比較
```

検証の入力と結果(`data/`)は、他者の動画の字幕を含むためリポジトリには含めていない。
